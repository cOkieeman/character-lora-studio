# 模型说明与标准发布包

## 适用范围

用于用户要求“写模型说明”“生成发布文案”“准备 Civitai 发布包”“做 Snippets”或整理未来发布包规则的任务。训练集 ZIP、正则集与丹炉交付继续遵循 [exports.md](exports.md)，不使用这里的模型发布目录。

默认使用 [model-publishing-template.md](model-publishing-template.md)。该文件包含填写规则、变量定义、由 `PUBLIC_TEMPLATE_START` / `PUBLIC_TEMPLATE_END` 注释界定的公开正文，以及版权说明候选。发布只提取已填写的公开正文，不复制内部规则、候选列表或 YAML 元数据。

## 从项目记录生成

1. 读取 `00_项目管理/角色配置.yaml`、项目状态、对应训练记录、选模结论和用户选图清单。读取实际模型文件和示例的生成参数，确认模型族、版本、触发词、checkpoint 与推荐参数。
2. 从 `character_source` 和已核实的设定来源自动选择版权候选；把确认结果及依据记录回项目配置。旧项目缺少字段时，先核实现有资料；没有证据就保持 `unknown`，不要从名字、画风或目录名猜测。
3. 对当前发布版本核对模型许可、上游/底模许可和用户选择的页面权限。填写实际许可证名称及全文链接；授权可来自多个文件或附加条款时全部列出，不为了满足单链接字段而漏掉适用条款。
4. 用当前版本事实填入模板。删除缺少资料的可选段落、首发版本的上一版对比、无负面提示词的整项。已知限制独立保留，即使是首发版本也不省略已确认的问题。完整提示词保持原样；推荐设置对应实际测试，实验计划不写成已经改善。
5. 按下方目录生成新包，用同一份确认数据生成正文、许可摘录、提示词文件和清单，避免内容冲突。完整发布包默认生成用户已认可的 `发布导航.html`，按下方“发布导航页面”规则制作。校验后更新项目状态及 `publication.releases`。

不要为未知许可设置默认的 MIT、CC、全商用或非商用条款；也不要默认禁止转载、合并或要求署名。角色来源用于选版权文案，不用于猜测模型许可证或商业权限。

## 自动选择版权文案

| 已确认的角色来源 | 选择的候选 | 依据与处理 |
| --- | --- | --- |
| `original` | 原创角色 | 已确认角色为原创，并记录设计者/权利方；使用者也可能训练他人的原创角色，不自动把权利归给模型发布者 |
| `fan` | 非官方同人角色 | 已确认原作名称及非官方、无官方授权的制作关系；作者/权利方未核实的可选行删除 |
| `authorized` | 已获授权的角色 | 授权状态为 `confirmed`，且有依据证明范围覆盖模型制作与发布；填写授权方和实际范围 |
| `unknown` 或记录相互冲突 | 来源或授权状态待确认 | 只生成草稿，并列出具体缺项；不宣称获得授权，也不宣称确认没有授权 |
| `not_applicable`，且概念为服装或画风 | 素材来源与版权 | 将角色来源标题改为“素材来源与版权”，按已确认素材来源署名，并说明模型许可不转授第三方素材权利；不虚构动漫角色 |

`authorized` 缺少授权依据或范围时退回待确认草稿。`fan` 与已确认的官方授权记录冲突时，先解决记录冲突，不静默任选一段。版权声明只说明来源与许可范围，不证明训练、发布或商业用途已经合法。

## 持久化字段

新增项目由 `assets/character-profile.template.yaml` 提供 `character_source` 与 `publication` 字段。旧项目只在相关任务需要时补入缺失字段，保留原有决定；不要重新初始化或覆盖整份配置。

每个 `publication.releases` 条目至少记录：

- `family`、`version`、`trigger_words`、最终模型的项目相对路径和 SHA-256。
- `tested_base_model`、实际推荐设置、提示词与样图记录的相对路径。
- `license.name`、`license.url`、适用上游许可和已核实的权限摘要；无法确认的值留空并记为待确认。
- `character_notice_variant`、来源/授权依据快照，避免以后更改角色配置时改写旧版声明。
- `package_path`、清单路径、ZIP 路径（若有）、生成日期、状态与待确认项。

状态使用 `draft` 或 `ready_local`。准备好本地包不代表已经公开发布；只有用户要求并实际完成上传/发布后，才另外记录真实发布 URL 和时间。

## 标准目录

按用户时区的日期建立新版本，不按修改时间猜测历史日期。同一版本的 Anima 与 Krea2 各有独立包；示例中的 `family` 使用稳定的 ASCII 标识，例如 `anima`、`krea2`。

```text
07_导出/模型发布/YYYY-MM-DD/family/
├─ character_id-family-version/
│  ├─ README.md                     发布导航与文件用途
│  ├─ 发布导航.html                  默认：可直接打开的互动文件导航
│  ├─ 模型说明.md                   填写完成的公开正文
│  ├─ 使用许可与版权.md             从同一正文提取的许可和来源声明
│  ├─ 推荐参数与提示词.md           从同一数据生成的实测设置与完整提示词
│  ├─ models/
│  │  └─ character_id-family-version.safetensors
│  ├─ examples/
│  │  ├─ 001_subject.png
│  │  └─ 001_subject.json           对应原图的生成参数
│  ├─ workflows/                    可选：可分享的实际工作流
│  │  └─ 001_subject.json
│  ├─ 展示画廊.html                 可选：本地预览，使用包内相对路径
│  ├─ manifest.json                 机器可读清单
│  └─ SHA256SUMS.txt                文件哈希，路径均为包内相对路径
└─ character_id-family-version-release.zip  需要 ZIP 时生成
```

### 命名与内容

- 包名只用稳定角色 ID、模型族及真实版本。选定 epoch/step 需要区分时加入版本标识，例如 `v013-ep24`；不要推断未核实的训练编号。
- 同一天同一包名已存在时，保留原包，创建 `-r02` 等修订包，并记录旧包路径及改动；不覆盖旧包或直接改旧包中的许可。
- 默认只包含选定的最终权重；用户需要备选 checkpoint 时，逐个标明用途与参数。重命名或复制不改变权重内容，复制后核对 SHA-256。
- 示例图采用用户确认的选图；保留原文件编码和参数，不为了统一后缀把 JPEG 内容改名为 PNG。使用连续编号与简短 ASCII 描述；图片、参数和工作流使用同一 stem。
- 参数 JSON 记录实际 prompt、negative prompt（如适用）、seed、底模、各 LoRA 与强度、采样器、步数、CFG、尺寸及对应文件名。字段缺失要明确标为未知，不伪造复现信息。
- 本地画廊只是浏览入口，不能作为参数记录的替代品。没有用户要求或现成预览需求时可省略，也不要创建空的可选目录。
- 发布包不放训练集、正则、淘汰图、全部中间权重、缓存、日志或内部审查记录。私有 API 密钥、账户数据和设备绝对路径不进入公开文案、清单或可分享工作流。
- 若用户只需要文案，直接提供 Markdown 文件；不要把空模型目录、空样图目录或不完整包标成正式发布包。

### 发布导航页面

用户已认可 [release-navigation.reference.html](../assets/release-navigation.reference.html) 的目录导航、深色页面、说明排版与面板切换。完整发布包默认沿用这一样式，生成包根目录的 `发布导航.html`；用户明确要求纯 Markdown 或不带 HTML 时遵从用户选择。

这个资产是可打开的视觉参考，包含演示数据，不是可以原样交付的成品。生成实际导航时：

- 保留左侧文件导航、右侧正文预览、标题加粗、触发词代码样式、横线分段和样图参数入口。
- 左侧导航来自当前包中实际存在的文件，不列空目录或不存在的示例。显示真实包名、模型族、版本、触发词和当前状态。
- “模型说明”“使用许可与版权”“推荐参数与提示词”面板使用相应 Markdown 文件的同一份最终内容。不要重新改写版权条件、提示词或参数。
- 一个包只对应实际模型族，不用参考页的 Anima/Krea2 按钮伪装成另一个模型族。只有另一模型族的包实际存在时，才以包间相对链接提供切换。
- 实际导航展示已经确认的版权声明，移除“原创/同人/已授权/来源待确认”的演示选择按钮。浏览者不能通过切换按钮改变角色来源或模型许可。
- 用实际选图替换示意图块，点击原图、参数或工作流入口时打开相应包内文件。未提供工作流时不保留无效入口。
- 所有包内资源使用相对路径；文案和清单内的文本按其 HTML/JSON 上下文转义，不将第三方文本当成可执行 HTML 或脚本。
- 导航页面应支持直接打开和离线浏览，样式与展示数据内嵌或来自包内资源，不依赖外部 CDN。不要依赖 `fetch` 本地 Markdown 文件才能显示正文。
- 正式交付移除“示例角色”、`demo_character`、演示说明和模板占位符。草稿仍显示真实待确认项，不能把演示占位符或空许可伪装成完整发布信息。

导航页面加入 `manifest.json` 文件清单及哈希校验。生成后检查文件导航、正文切换、触发词排版、原图/参数链接，以及页面内容和实际文件的一致性。

### README 与许可文件

`README.md` 简要标明模型名称、模型族、版本、触发词、选定权重以及每个文件的用途，指向包内相对链接。它是发布导航，不混入插件内部操作规则。

`使用许可与版权.md` 与 `模型说明.md` 中的许可和版权段落必须一致。已取得适用的许可全文且可再分发时，可在 `licenses/` 附上原文；不要把许可摘要命名为原始 LICENSE 全文，也不要仅写“以页面为准”来替代已经可确认的许可证链接。

### 清单与 ZIP

从 [release-manifest.template.json](../assets/release-manifest.template.json) 填写 `manifest.json`。这是空结构样板，不是已经确认的模型信息。`null` 表示未知，`false` 表示明确禁止，二者不能混淆；空文件列表不证明包可发布。

- 文件清单记录包内相对路径、用途、字节数与 SHA-256，不写设备绝对路径。
- 对模型、文档、示例图、参数 JSON、工作流和可选许可原文计算哈希，填入 `manifest.json`。
- `manifest.json` 的 `files` 不包含它自己或 `SHA256SUMS.txt`，避免自引用；`SHA256SUMS.txt` 覆盖其他所有文件及最终 `manifest.json`，不包含自身或旁边的 ZIP。
- ZIP 保留一个与包名相同的顶层目录，不把 ZIP 放进包目录，也不在压缩包中重复包含其他发布 ZIP。
- 生成 ZIP 后解压到独立临时目录，对照清单验证路径、大小和哈希，再报告压缩包有效。

## 完成检查

发布文案应无残留变量或内部填写提示。许可、来源或必需测试资料缺失时，把待确认列表放在独立的草稿交付说明里，不隐藏缺项，也不把免责声明当作授权。

完整模型包需确认权重、当前版本说明、许可版权信息、已选示例与实际参数对应；文件清单及 SHA-256 校验通过。检查没有将不同模型族的权重、触发词和参数混在同一包中。

整理规则本身不授权修改已有发布包、训练启动、上传或公开发布。用户请求旧包整理时，采用新目录复制并验证的方式，保留旧包与迁移记录。
