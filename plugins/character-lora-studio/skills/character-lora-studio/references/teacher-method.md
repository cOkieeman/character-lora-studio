# 老师方法：决策规则

## 核心目标

让触发词稳定召回角色，同时让服装、动作、构图和背景仍可替换。不要把“删除标签”等同于“模型不再学习该内容”；caption 只决定训练时如何分配概念。

## 三类特征

1. **固定身份**：脸型、关键发型、瞳色、核心发饰、特殊形态。必须在图像中稳定。
2. **可控身份**：希望提示词显式控制的发饰、服装或道具。保留规范标签，并加入测试提示词。
3. **变量**：姿势、表情、镜头、背景、光照、普通服装。逐图如实打标，用于解绑。

每个角色都要在 `角色配置.yaml` 中明确这三类。用户决定优先于默认建议。

## 触发词

- 使用唯一 ASCII 小写触发词，例如 `mirellevane`。
- 人形 caption 通常以 `1girl, <trigger>, solo` 开始。
- 触发词拼写必须在全部训练 caption、测试提示词和发布说明中一致。
- 触发词单独召回与“触发词 + 完整身份标签”都要测试。后者不是说每次必须输入全部标签，而是用于确认细节上限。

## 标签保留原则

- 保留画面真实存在、且需要模型可理解或可控制的标签。
- 同一固定特征若希望主要绑定触发词，可少标或不标；若希望可单独开关，则稳定保留其 canonical tag。
- 不要机械套用另一角色的保留表。`hair ornament`、`hanfu`、`necklace` 等是否保留由本角色目标决定。
- 衣服需要可替换时，必须逐图标注实际服装，且准备足够换装数据。

## 正则集

- 正则用于维持通用先验，不是角色补图。
- 正则 caption 不得包含角色触发词。
- 排除与目标角色过近的发型、发饰、专属服装和道具组合。
- 抓取数量可比目标多约 10 张，再人工删除人体、构图、色彩或线条混乱的图。
- 保留最终正则集及 caption，作为可复用独立资产导出。

## 不确定性

老师截图、平台 UI 和模型版本可能变化。遇到未验证参数时：

1. 记录来源和日期。
2. 将其标为项目配置而不是硬规则。
3. 用固定 seed 和对照提示词验证。
